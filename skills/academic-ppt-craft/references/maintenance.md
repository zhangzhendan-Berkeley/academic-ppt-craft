# 持续维护与交接

## 维护的是可执行偏好，不是聊天堆积

后续用户补充或否决某项要求时，本轮就更新实际文件：

1. 判断作用域：长期审美／教学偏好、当前模板参数、某门课主线、一次局部修订，或仍待审核的想法。
2. 将有效要求写入对应专题；有冲突就替换旧规则。不要在文件顶部无限追加互相矛盾的“最新要求”。
3. 对易误解规则保留简短理由和前后例子；案例标明是教师原话还是agent建议。
4. 更新preferences的范围／优先级及入口的版本日期。模板变化更新原件、结构档案和学习指南。
5. 对当前项目检查同类问题，维护进度和源码；修改skill不代替实际课件修正。
6. 同步已安装副本与交接包，校验相对链接、附件和哈希。只同步本skill自己的文件，不覆盖其他用户技能。

不能承诺没有会话时在后台自动更新。实际承诺是：后续参与此用户课件工作时读取并维护这份记录，而不只在聊天中说“记住了”。

## 唯一有效规则与历史适配

公共方法以本skill为准；教师模板与个人选择进入课程简报。不要从旧课程目录激活新课不需要的主题或阶段限制。

若项目里存在本skill源码副本，以项目副本维护并同步本机安装；若接手者只拿到压缩包，解压得到的完整文件夹就是维护源。不依赖原作者D盘路径。版本号使用实际修订号，用户新要求生效日写日期，不能把待审核建议标记为已确认。

## 压缩包与附件

压缩包应含一个完整`academic-ppt-craft/`目录，SKILL.md、agents配置、所有引用文档、登记模板、SOP和范例都在其中。附件清单写明原来源、用途、完整／节选、原页码、是否含视频。每次新增附件先核对使用范围，不把一个大素材目录递归全收进去。

[package_skill.py](../scripts/package_skill.py) 按已登记附件白名单收集文件，检查本地Markdown链接、生成SHA256清单并打包。附件本身的来源与阅读用途见examples.md；哈希校验只能说明完整性，不能代替打开PPT或教学审校。

运行示例（从skill所在父目录执行，路径可自选）：

```text
python academic-ppt-craft/scripts/inspect_template.py academic-ppt-craft/assets/ppt-template.pptx --output academic-ppt-craft/assets/template-profile.json
python academic-ppt-craft/scripts/package_skill.py academic-ppt-craft --output academic-ppt-craft_v1.0.0.zip
```

把完整目录放到目标Codex实际使用的skills目录后，在新会话中使用`$academic-ppt-craft`。这里仅说明文件包的使用；如果目标客户端路径或技能发现机制不同，应检查当地配置，不假设原机器路径。

## 交接检查场景

以下用于维护者自查预期行为，不冒充已开展的独立agent实验：

- 新课只给标题：先读取可用材料，输出分工清单，优先问受众／课时／课程边界，不继承触觉内容。
- 已有审核大纲：直接推进授权制作，不重新访谈和索要样板审批。
- 模板换了：重新测量原生对象，不把15页模板对象ID套到新文件。
- 用户只修页脚：保留正文和手改，文章以外来源转备注，检查全稿同类项。
- 用户说视频改用另一格式：记录新的明确偏好，取代WMV默认并检查兼容，不能两种要求同时声称必须。
- 只有分享包：全部链接可用，模板和范本可打开，无需原项目；没有私密汇报原件或截图。
